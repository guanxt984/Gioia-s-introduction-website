本文使用三类标记区分信息可信度：

- **实测**：通过浏览器读取实际渲染结果或自动化提取获得。
- **观察**：通过桌面端、移动端截图和滚动体验判断。

## 2. 核心设计结论

COVEO 的设计可以概括为：

> 以严格的瑞士式信息系统为骨架，以独立杂志、唱片视觉和梦境式动效作为感性表层。

它最重要的能力不是“做得像音乐网站”，而是让以下两组气质同时存在：

| 理性系统 | 感性表达 |
| --- | --- |
| 统一编号 | 漂浮作品封面 |
| 极细分隔线 | 环形空间构图 |
| 信息索引 | 摄影和拼贴 |
| 等宽元数据 | 手写字体 |
| 无衬线正文 | 高反差衬线标题 |
| 统一基线 | 不对称视觉素材 |
| 克制中性色 | 高饱和橙色强调 |

六个核心风格关键词：

1. 编辑式
2. 克制
3. 梦境感
4. 艺术档案
5. 轻微复古
6. 数字实验性

对个人作品集最有价值的原则是：

> 场景可以自由，信息必须对齐；视觉可以感性，内容必须可检索。

## 3. 信息架构与页面节奏

### 3.1 页面主结构

COVEO 首页采用长滚动单页结构，主要顺序为：

1. 首屏品牌与可交互作品轨道
2. 创作者与项目故事
3. 完整作品索引
4. 大幅视觉收束
5. 致谢与项目宣言
6. 页脚与外部链接

### 3.2 信息节奏

页面遵循“感受 → 理解 → 检索 → 收束”的节奏：

- 首屏先让用户感受品牌世界。
- 中段解释创作背景和创作者动机。
- 后段以高效率的作品列表提供完整信息。
- 最后使用大幅视觉与致谢完成情绪收束。

这种结构避免艺术表达与信息检索互相冲突。首屏可以非常自由，列表区则重新回到严格秩序。

### 3.3 单屏原则

COVEO 的多个区段都遵循“一个视口只突出一个主概念”：

- 首屏：中心人物与环形作品
- 故事区：创作者叙事
- 作品区：完整作品档案
- 致谢区：视觉宣言

页面没有用同尺寸卡片网格填满每一屏，而是让不同章节拥有不同的艺术处理方式。

## 4. 色彩系统

### 4.1 CSS 颜色变量（实测）

```css
:root {
  --color-black: #000000;
  --color-white: #ffffff;
  --color-cream: #eeeeee;
  --color-cream-dark: #dddddd;
  --color-cream-dark-hover: #cdcdcd;
  --color-ink: #1d1812;
  --color-ink-muted: #524d46;
  --color-ink-muted-inverted: #747474;
  --color-orange: #fe5416;
  --color-border: rgba(0, 0, 0, 0.20);
  --color-border-muted: rgba(0, 0, 0, 0.07);
  --color-border-inverted: rgba(255, 255, 255, 0.20);
}
```

### 4.2 颜色角色

| 角色 | 色值 | 典型用途 |
| --- | --- | --- |
| 页面背景 | `#EEEEEE` | 全站底色、画布 |
| 主文字 | `#1D1812` | 标题、正文重点、链接 |
| 次级文字 | `#524D46` | 说明文字、辅助元信息 |
| 纯黑 | `#000000` | 强对比按钮、少量图形 |
| 白色 | `#FFFFFF` | 深色背景上的反白信息 |
| 浅灰控件 | `#DDDDDD` | 胶囊按钮、弱容器 |
| Hover 灰 | `#CDCDCD` | 控件悬停反馈 |
| 强调橙 | `#FE5416` | 中心头像背景、主视觉、Hover 强调 |
| 普通边框 | `rgba(0,0,0,.20)` | 小型按钮、标签 |
| 弱边框 | `rgba(0,0,0,.07)` | 作品行、分隔线、轻轮廓 |

### 4.3 色彩策略

COVEO 采用“克制中性色 + 单一高饱和强调色”的策略：

- 页面绝大部分由暖灰、暖黑和灰棕构成。
- 彩色主要来自作品图像和橙色品牌视觉。
- UI 控件很少使用强色填充。
- 强调色不是平均分布，而是集中在记忆点和交互状态。
- 低饱和背景让摄影和唱片封面成为真正焦点。

### 4.4 色彩空间关系

- 背景与组件多数处于同一浅灰色域，通过边框、位置和内容建立层级。
- 页面很少使用纯白卡片覆盖灰色背景。
- 不依赖大面积阴影制造浮层感。
- 橙色主要承担视觉锚点，而非状态色全集。

### 4.5 对作品集的应用建议

- 保留 COVEO 的“中性色画布 + 一个高饱和重点色”逻辑。
- 小女孩、照片、经历岛和项目图片承担主要色彩。
- 强调色用于当前子岛、关键链接、选中技能和联系行动。
- 不建议三类经历分别使用三种高饱和主题色。
- 中文正文需要比 COVEO 原站更高的明度对比。

## 5. 排版与字体系统

### 5.1 字体角色

COVEO 实际形成三层字体语言：

#### A. Inter 无衬线字体

用途：

- 品牌名称
- 正文
- 导航
- 作品名称
- 说明文字
- 按钮
- 大部分 UI 信息

气质：理性、现代、中性、易于建立信息系统。

#### B. Eiko 高反差衬线字体

用途：

- 大型情绪标题
- 强调“Storytelling”等艺术叙事词汇

气质：时尚编辑、艺术出版、唱片封面、情绪化。

#### C. 等宽字体

用途：

- 编号
- 时间
- 播放提示
- 版本信息
- 作品元数据
- 小型操作按钮

气质：档案、设备界面、编号系统。

### 5.2 实测字体尺寸

| 角色 | 字体 | 字号 | 字重 | 其他 |
| --- | --- | ---: | ---: | --- |
| 大型展示标题 | Eiko | `60px` | 400 | 字距约 `-1.2px` |
| 小型品牌标题 | Inter | `14.4px` | 600 | 常规字距 |
| 正文 | Inter | `12px` | 400 | 行高约 `24px` |
| 小标题 | Inter | `12px` | 600 | 部分全大写 |
| 列表标题 | Inter | `12px` | 600 | 全大写 |
| 元信息 | Inter / Mono | `10.2px` | 400–500 | 常用全大写 |
| 小提示 | Mono | `10.8px` | 400 | 中心或边缘提示 |
| 极小辅助信息 | Inter | `9.6px` | 400–600 | 常用全大写 |
| 更小标签 | Inter | `8.4px` | 400–600 | 少量使用 |

### 5.3 字体层级原则

COVEO 并不依赖大量字号建立层级，而依赖：

- 字体类别
- 大小写
- 字重
- 颜色深浅
- 空间位置
- 对齐关系
- 大标题和小信息之间的极端比例

### 5.4 正文规范

- 实测正文宽度约 `366px`。
- 实测正文字号 `12px`，行高 `24px`，约为字号的 2 倍。
- 次级正文颜色为 `#524D46`。
- 段落之间通过大于行高的垂直距离分组。
- 长文区域不追求铺满容器，而保持窄栏阅读。

### 5.5 标题组合

典型标题结构：

1. 小型无衬线标题提供理性主题。
2. 大型衬线或手写标题提供情绪表达。
3. 两者不一定严格在同一行或同一基线。

这形成“信息标题 + 情绪标题”的双层语义。

### 5.6 中文适配建议

COVEO 的原始小字号不适合直接用于中文：

| 中文角色 | 建议字号 | 建议行高 |
| --- | ---: | ---: |
| 中文正文 | `14–16px` | `1.7–1.9` |
| 辅助信息 | `12–13px` | `1.5–1.7` |
| 标签 | `11–12px` | `1.3–1.5` |
| 卡片标题 | `16–22px` | `1.3–1.5` |
| 页面大标题 | `48–80px` | `1.0–1.2` |

推荐保持三种字体角色，但不直接照搬字体：

- 现代黑体：产品信息、简历、正文
- 有出版气质的宋体：情绪标题、结束语
- 中文兼容等宽字体：编号、日期、城市、标签

### 6.2 建议归纳后的间距令牌

| 令牌 | 建议值 | 用途 |
| --- | ---: | --- |

| `space-7` | `36px` | 内容组之间 |
| `space-8` | `48px` | 章节内部大间距 |
| `space-9` | `72px` | 建议补充的中大型节奏 |
| `space-10` | `144px` | 章节留白 |
| `space-11` | `216px` | 戏剧性章节分隔 |

### 6.3 间距使用规律

- 小间距主要集中在 `10–12px`。
- 内容组常用 `24–48px`。
- 章节切换直接跳到 `144–216px`。
- 中间档位使用较少，因此页面节奏有明显松紧变化。
- 大留白不是空缺，而是叙事停顿。

### 6.4 对作品集的建议

- 不要所有页面都使用均匀的 `64px` 区块间距。
- 简历页使用紧凑节奏。
- 经历岛与技能云海使用更大空间停顿。
- 关键转场可以使用接近一个完整视口的空间距离。

## 7. 栅格规范与布局基线

### 7.1 桌面端实测基线

测试视口：`1280 × 720px`。

| 项目 | 实测值 |
| --- | ---: |
| 页面渲染宽度 | 约 `1265px`（扣除滚动条） |
| 主要内容左边距 | `64px` |
| 主要内容右边距 | 约 `64px` |
| 主要作品列表宽度 | `1137px` |
| 页脚外边距 | `24px` |
| 正文窄栏宽度 | 约 `366px` |
| 作品列表行高 | 约 `100px` |
| 作品列表横向内边距 | `12px` |

### 7.2 桌面端布局逻辑

- 页面不是统一十二列企业栅格的直观表现，而是“固定外边距 + 内部自由构图”。
- 作品列表使用接近满宽的稳定信息基线。
- 故事正文使用窄栏居中或偏中布局。
- 图片可以越过正文网格，但正文不偏离阅读基线。
- 首屏采用中心轴对称作为视觉锚点，外围素材故意不规则。
- 页面边缘允许存在竖排信息和越界视觉。

### 7.3 移动端实测基线

测试视口：`390 × 844px`；实际内容宽度约 `375px`（扣除滚动条）。

| 项目 | 实测值 |
| --- | ---: |
| 主要内容左边距 | `12px` |
| 主要内容宽度 | `351px` |
| 页脚左右边距 | `24px` |
| 作品列表行高 | 约 `76px` |
| 列表图片 | 约 `48 × 48px` |
| 列表操作按钮 | 约 `72 × 32px` |
| 中心头像 | 约 `100 × 100px` |

### 7.4 响应式断点

自动提取到的主要断点为：

```css
@media (min-width: 768px) { ... }
```

可以判断其核心策略是：

- `< 768px`：移动端紧凑布局
- `≥ 768px`：桌面/平板扩展布局

### 7.5 移动端内容折叠规则

桌面作品行通常显示：

- 编号
- 封面
- 作品名称
- 日期
- 类型与歌曲数量
- 时长
- Preview 操作

移动端则隐藏：

- 编号
- 类型与歌曲数量
- 时长
- 播放图标

移动端保留：

- `48px` 封面
- 作品名称
- 日期
- `72px` 宽 Preview 按钮

这体现出明确的响应式优先级，而非简单整体缩放。

### 7.6 布局基线原则

1. 信息行内所有项目共享水平中心线。
2. 作品缩略图、标题与操作按钮形成三段式布局。
3. 元信息附着于标题，而不是独立漂浮。
4. 桌面端允许信息横向展开；移动端只保留识别与行动所必需的内容。
5. 不使用大量独立卡片作为默认布局。

## 8. 圆角、边框与阴影

### 8.1 圆角系统（实测）

| 值 | 主要元素 | 可信度 |
| --- | --- | --- |
| `4px` | 小型工具按钮、标签 | 中低 |
| `6px` | 小型按钮 | 低 |
| `8px` | Modal 或小容器 | 低 |
| `12px` | 大型内容图片 | 高 |
| `24%` | 作品封面缩略图 | 高 |
| `40px` | 胶囊按钮 | 高 |
| `50%` | 圆形头像或装饰 | 中 |
| `100%` | 圆形按钮、完全圆形图片 | 中 |

### 8.2 圆角使用逻辑

- 大图使用克制的 `12px` 圆角。
- 小封面使用比例圆角 `24%`，形成柔软但非标准胶囊的轮廓。
- 操作按钮使用全胶囊。
- 工具型按钮保持 `4–8px` 小圆角。
- 不使用大圆角卡片包裹所有内容。

### 8.3 边框系统

典型边框：

```css
border-color: rgba(0, 0, 0, 0.07);
border-color: rgba(0, 0, 0, 0.20);
```

作品列表主要使用：

- `1px` 极淡点状分隔线
- 部分位置使用上下分隔
- 链接可使用点状下划线

### 8.4 阴影系统

网站几乎不使用传统卡片阴影。提取到的典型轮廓阴影：

```css
box-shadow: 0 0 0 1px rgba(0, 0, 0, 0.07);
```

它本质上是轮廓线，而非空间投影。

### 8.5 空间层级原则

- 层级主要由尺寸、位置、遮挡和运动产生。
- UI 层级主要由文字深浅和细线产生。
- 浮层不依赖强阴影。
- 图像叠压承担主要空间感。

## 9. 图片与视觉素材规范

### 9.1 首屏作品缩略图

- 围绕中心人物形成完整圆周。
- 每张图存在不同旋转角度。
- 尺寸略有变化。
- 圆角约 `24%`。
- 通过滚动改变轨道位置。
- 进入视口时分批显现。
- 既是装饰，也是可点击的试听入口。

### 9.2 内容摄影

- 大图常用 `12px` 圆角。
- 摄影与文本错位排列。
- 实物图像可以越过图片边界形成拼贴。
- 图像不是均匀卡片网格，而是服务于故事段落。

### 9.3 高冲击视觉组合

致谢区典型组合：

- 黑白摄影底图
- 高饱和橙色封面叠加
- 大型高反差衬线字
- 手写文字跨越图层
- 左右大留白不对称布局

### 9.4 图像原则

- 一个决定性的主视觉优于多个弱图片。
- 图片承担品牌色彩，UI 保持中性。
- 图片形状、角度和层叠关系形成节奏。
- 图片必须参与交互或叙事，不作为无意义装饰。

## 10. 组件规范

### 10.1 胶囊按钮

实测近似规范：

```css
.button-pill {
  min-height: 32px;
  padding: 10.2px 18.36px;
  border: 0;
  border-radius: 40px;
  background: rgba(0, 0, 0, 0.10);
  color: #1d1812;
  font-family: monospace;
  font-size: 10.2px;
  font-weight: 400;
  text-transform: uppercase;
}
```

Hover：

```css
.button-pill:hover {
  background: #cdcdcd;
  color: #fe5416;
}
```

### 10.2 黑色主按钮

实测特征：

- 黑色背景
- 白色文字
- `40px` 胶囊圆角
- 字号约 `12px`
- 字重约 600
- 适合播放器中的主要继续操作

### 10.3 圆形播放按钮

- 完全圆形
- 极淡 `1px` 边框
- 透明背景
- 图标居中
- Hover 改变边框或强调颜色

### 10.4 小型方形工具按钮

实测近似：

- `4px` 圆角
- `1px solid rgba(0,0,0,.2)`
- 透明背景
- 内边距约 `9.6px`
- 用于关闭 Modal 或次级工具操作

  color: #524d46;
  background: transparent;
  font-size: 9.6px;
  font-weight: 400;

#### 桌面端

- 容器宽约 `1137px`
- 行高约 `100px`
- 左右内边距 `12px`
- 上下使用极淡点状分隔线

- 只显示名称与日期

### 10.7 作品缩略图

- 首屏轨道：约 `40–102px` 动态尺寸
- 移动端轨道：约 `40–60px`

## 11. 动效系统

### 11.1 动效分类

COVEO 使用四类主要动效：

1. 首屏轨道随滚动旋转
2. 图像进入视口时渐显与位移恢复
3. 标题从模糊过渡到清晰
4. Hover 时的弹性位移、缩放和颜色变化

### 11.2 进入动画

实测典型曲线：

```css
transition:
  transform 1s cubic-bezier(0.25, 1, 0.5, 1),
  opacity 1s;
```

特征：

- 持续时间约 `1s`
- 强 ease-out
- 物体快速获得动势，缓慢停下
- 不使用线性或默认 ease 作为主要场景动效

### 11.3 列表错峰动画

图片进入视口时使用递增延迟：

```text
0.05s
0.10s
0.15s
...
1.05s
```

这使一组作品按顺序出现，但每项动作保持相同，建立档案展开感。

### 11.4 Hover 弹性

首屏作品按钮使用近似：

```css
transition:
  transform 0.35s cubic-bezier(0.3, -0.46, 0.6, 2.1),
  opacity 1s,
  filter 0.75s;
```

该曲线会产生明显超调，带来“柔软物体被触碰”的感觉。

### 11.5 模糊进入

部分标题采用：

```css
filter: blur(...) -> blur(0);
transition: filter 1s 0.2s;
```

适合情绪型标题，不用于长正文和操作元素。

### 11.6 按钮动效

典型按钮：

```css
transition:
  background 0.3s,
  transform 0.3s cubic-bezier(0.34, 1.56, 0.64, 1);
```

### 11.7 滚动动效规律

- 首屏轨道不是独立循环动画，而与滚动位置建立关系。
- 滚动时中心人物保持稳定，外围内容发生空间变化。
- 中段图像和文字以不同速度进入视觉区域。
- 大场景动效约 `0.75–1s`。
- 小交互动效约 `0.2–0.4s`。
- 不使用闪烁、霓虹光效或大量粒子。

### 11.8 对作品集的建议

可迁移的动效规则：

- 小女孩与纸飞机作为稳定锚点。
- 经历岛旋转与拖动或滚动建立关系。
- 前方子岛使用缓慢 ease-out 放大。
- 技能条使用小幅漂浮，不应持续高频摆动。
- 项目列表使用轻微错峰进入。
- 资料卡使用模糊到清晰或遮罩展开。
- 坠落转场是全站唯一明显加速动作，形成戏剧高潮。

必须补充：

```css
@media (prefers-reduced-motion: reduce) {
  /* 取消轨道旋转、坠落和漂浮；改为淡入或直接切换 */
}
```

## 12. 交互系统与 UX 原则

### 12.1 可交互对象即内容对象

首屏封面既是视觉构图，也是试听入口。网站没有另外创造与内容无关的装饰按钮。

对作品集而言：

- 子岛本身就是经历分类入口。
- 技能条本身就是技能详情入口。
- 纸飞机是转场载体，不额外增加“下一页”装饰按钮。

### 12.2 自由探索与完整索引并存

- 首屏允许自由选择作品。
- 后段仍提供完整按时间排序的作品列表。

这可以映射为：

- 经历岛负责自由探索。
- 简历页负责完整信息索引。

### 12.3 反馈类型

COVEO 主要使用以下反馈：

- 位移
- 缩放
- 颜色变化
- 背景变化
- 模糊清晰度
- 音频播放状态

它很少使用 Toast 或显眼提示框。

### 12.4 可发现性

原站使用“Click to preview song / Tap artwork to preview a song”作为交互提示。桌面与移动端文案不同。

作品集应使用相同原则：

- 桌面端：“拖动旋转经历岛”
- 移动端：“左右滑动选择经历”
- 技能云海：“点击技能条查看相关经历”

### 12.5 不强制路径

COVEO 允许用户选择任意作品试听，也允许继续滚动查看列表。作品集同样不应要求用户看完三个子岛才能进入技能页。

## 13. 响应式设计详解

### 13.1 首屏轨道

桌面端：

- 轨道覆盖较大画幅。
- 封面尺寸约 `70–102px`。
- 中心人物位于视口中央。
- 左侧可放竖排文案。

移动端：

- 轨道仍保留完整圆形概念。
- 封面缩小到约 `40–60px`。
- 部分轨道元素允许超出屏幕边缘。
- 中心头像约 `100px`。
- 操作提示放在下方居中。
- 竖排长文案不再作为主要可读内容。

### 13.2 正文区

- 桌面端采用图片、正文和装饰物错位组合。
- 移动端优先改为单栏。
- 图片宽度接近内容区 `351px`。
- 正文保持完整，不应横向压缩成多列。

### 13.3 作品索引

- 桌面端展示完整元数据。
- 移动端主动删除低优先级字段，而不是让文字换成多行小字。
- 行高从 `100px` 缩为 `76px`。
- 操作按钮仍始终可见。

### 13.4 大留白

移动端仍保留非常大的纵向留白，而非把所有章节压紧。这说明留白属于品牌节奏，而不是桌面端偶然产生的空白。

### 13.5 对作品集的响应式建议

- 经历岛桌面端采用左信息、右岛屿；移动端改为上方岛屿、下方详情。
- 移动端不保留复杂三维拖拽，可以改为横向滑动或分段选择器。
- 纸飞机与女孩可保持画面中心，但缩小运动范围。
- 简历页移动端隐藏部分次要字段，详情点击展开。
- PDF 下载入口在移动端需缩为图标加短文字，避免挡住页面。

## 14. 可访问性与风险

### 14.1 原站优势

- 主要作品具有可读链接结构。
- 播放按钮具有可访问名称。
- 列表结构清晰。
- Hover 通常伴随颜色和形变，不只依赖一种反馈。
- 移动端对信息进行了主动取舍。

### 14.2 原站风险

#### 字号过小

大量 `9.6–12px` 文字对中文和低视力用户不友好。

#### 次级文字对比偏弱

`#524D46` 在 `#EEEEEE` 上通常可读，但极小字号会增加阅读压力。

#### 交互提示较隐蔽

首屏提示为极小等宽文字，用户可能把作品轨道当成纯装饰。

#### 依赖运动理解空间

如果禁用动画，必须确保内容和选择状态仍然清楚。

#### 移动端轨道存在越界

越界是视觉策略，但不能让点击对象大部分位于屏幕外。

### 14.3 本项目必须增加的规则

- 正文对比度至少达到 WCAG AA。
- 中文正文不小于 `14px`。
- 所有点击对象建议至少 `44 × 44px`。
- 经历岛必须提供文本替代入口。
- 所有弹窗可通过键盘关闭。
- 焦点状态不能只使用颜色变化。
- 支持 `prefers-reduced-motion`。
- 动画未执行时，内容默认仍可见。

## 15. 设计优势与局限

### 15.1 优势

1. 首屏具有极强记忆点。
2. 艺术表达和完整索引并存。
3. 交互与内容主题统一。
4. 颜色系统非常克制。
5. 通过图像承担品牌色彩，UI 不喧宾夺主。
6. 页面不同章节拥有不同艺术处理，但整体语气一致。
7. 响应式不是缩小桌面版，而是重排信息优先级。

### 15.2 局限

1. 原站小字号不适合中文招聘作品集。
2. 艺术表达优先，信息查找速度不是最高。
3. 首屏交互提示不够显眼。
4. 大留白可能被招聘者理解为加载不完整。
5. 动态轨道和滚动效果具有较高实现成本。
6. 如果直接复制，会非常像音乐或设计师作品集，削弱产品经理身份。

## 16. 对 AI 产品经理作品集的迁移框架

### 16.1 应当继承的设计基因

1. 克制的中性色背景。
2. 单一高饱和强调色。
3. 理性字体与情绪字体的反差。
4. 等宽字体构成的档案信息。
5. 大留白与小型元信息。
6. 中心锚点与外围旋转内容。
7. 编号化完整索引。
8. 轻边框、少阴影。
9. 图片错位与拼贴。
10. 大场景慢动效、小交互快动效。
11. 桌面信息完整、移动信息主动精简。

### 16.2 不应直接复制的形式

- 唱片封面圆环的具体视觉。
- Eiko 和 Inter 的原样组合。
- 全站极小字号。
- 音乐播放器按钮样式。
- 大量英文大写标签。
- 黑白摄影叠橙色唱片封面的具体组合。
- 作品编号直接变成所有页面的装饰编号。

### 16.3 五个页面的对应关系

#### 启程页

- 借鉴中心式构图和大留白。
- 真实照片为唯一视觉焦点。
- 联系方式使用小型档案排版。
- 背景可出现极淡飞行轨迹。
- 照片向数字小女孩转化是本项目独有记忆点。

#### 简历页

- 借鉴 Discography 的完整索引。
- 使用稳定的时间、地点、岗位和结果基线。
- 不采用大量白色卡片。
- 桌面完整展示，移动端隐藏次要字段。

#### 经历岛

- 借鉴“中心稳定、外围旋转”的空间逻辑。
- 女孩和纸飞机固定，经历岛旋转。
- 前方子岛放大并提高对比度。
- 后方子岛缩小并降低对比度。
- 左侧详情保持严格网格。

#### 技能云海

- 技能条借鉴胶囊按钮和等宽标签。
- 云朵和女孩负责感性表达。
- 资料卡采用编辑式排版与轻轮廓。
- 技能必须关联具体项目证据。

#### 抵达终点

- 借鉴致谢区的双栏大留白。
- 一侧是女孩与场景，一侧是联系信息。
- 结束语使用情绪型字体。
- 联系方式和 PDF 下载保持理性排版。

## 18. 后续设计检查清单

### 视觉

- 是否保持一个明确视觉锚点？
- 是否只有一个主强调色？
- 图片是否承担主要色彩？
- 场景自由时，文字是否仍然严格对齐？
- 是否避免了默认 SaaS 卡片网格？

### 信息

- 招聘者能否快速找到简历、经历、技能和联系方式？
- 动画之外是否存在完整文本内容？
- 每项技能是否有经历证据？
- 移动端是否主动删减低优先级字段？

### 交互

- 用户是否知道经历岛可旋转？
- 当前子岛是否有明确选中反馈？
- 所有交互目标是否至少约 `44 × 44px`？
- 无 Hover 的移动端是否仍有完整反馈？
- 动画关闭后是否仍能完成全部操作？

### 动效

- 大场景是否使用约 `0.75–1s` 的强 ease-out？
- 小交互是否控制在 `0.2–0.4s`？
- 是否只在同一组列表中使用错峰？
- 是否避免每一段内容都使用相同淡入？
- 是否提供 reduced-motion 版本？

### 排版

- 中文正文是否至少 `14px`？
- 正文行宽是否控制在约 `65–75` 个字符？
- 情绪标题与信息标题是否承担不同角色？
- 等宽字体是否只用于真正的元信息？
