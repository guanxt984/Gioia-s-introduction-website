# AI 产品经理个人作品集网站设计文档

更新日期：2026-07-22  
项目状态：创意设计阶段  
求职方向：AI 产品经理（AI 视觉、创意工具、ToC 产品、Agent）

## 1. 项目目标

设计一个具有鲜明个人创意、同时能高效传达求职信息的个人作品集网站。

网站不是传统简历的网页复刻，而是一段连续的空中探索旅程。用户通过自然向下滚动，跟随主角依次了解个人信息、项目经历、专业能力与联系方式。

网站需要同时达到以下目标：

1. 让招聘者快速确认候选人的身份、求职方向和基本条件。
2. 清晰展示四段实习、两至三个学校项目及个人 AI 实践。
3. 用具体经历为每项能力提供证据，而非只罗列技能关键词。
4. 通过统一的世界观和连续转场突出候选人的创意表达与产品思维。
5. 在完整体验之外，为时间有限的招聘者提供快速导航；PDF 简历下载入口始终悬浮在网站右上角。

## 2. 核心创意

### 2.1 世界观

整个网站是一个虚拟的空中悬浮世界。真实照片中的“我”逐渐转化为数字化小女孩，坐上一架由简历纸折成的纸飞机，向下进入自己的经历世界。

主角、纸飞机、经历岛和技能云海共同形成统一叙事：

> 我的过往被折成纸飞机，载着数字化的我进入经历世界；经历沉淀为能力，能力带我抵达下一段旅程。

### 2.2 核心视觉角色

- **数字化小女孩**：候选人的数字分身，而非独立的虚构角色。
- **纸飞机**：由页面中的简历纸或个人介绍卡片折叠而成，代表履历、想法与行动。
- **经历岛**：代表候选人做过的事情，由三个经历区域构成。
- **技能云海**：代表由经历沉淀出的能力、方法和经验。

### 2.3 纸飞机约束

纸飞机保持普通、轻盈的纸张形态：

- 不设置驾驶舱。
- 不增加机械结构。
- 不增加科技光带。
- 不将其包装成高科技载具。
- 可以保留简历纸原有的少量文字、纸张纹理或折痕。

## 3. 内容资产

### 3.1 实习经历

- 共四段实习经历。
- 实习地点分别为杭州、上海、北京、深圳。
- 实习是作品集最重要的经历内容之一。

每段实习建议准备：

- 公司与岗位
- 实习时间和地点
- 项目背景
- 用户或业务问题
- 个人职责
- 产品判断与方案
- 协作过程
- 结果与数据
- 复盘与收获

### 3.2 学校项目

- 选择两至三个重点项目。

每个项目建议准备：

- 项目主题
- 目标用户
- 个人角色
- 调研与设计过程
- 最终成果
- 验证结果或反馈

### 3.3 个人 AI 实践

包括但不限于：

- Vibe Coding 项目
- Coze 工作流
- Agent 实验
- AI 视觉创作
- Prompt 或自动化实践

个人 AI 实践需要说明解决了什么问题、形成了什么成果，以及如何迭代，避免仅罗列工具名称。

## 4. 网站信息架构

网站由五个连续章节构成：

1. 启程页
2. 简历页
3. 经历岛
4. 技能云海
5. 抵达终点

整体空间方向以自然向下滚动为主：

> 现实中的我 → 数字化分身 → 乘纸飞机下行 → 经历岛 → 跳下纸飞机 → 技能云海 → 穿过云层 → 抵达终点

## 5. 页面设计

### 5.1 启程页：认识我

#### 页面目标

让招聘者快速了解候选人是谁、求职什么岗位，以及主要关注方向。

#### 页面内容

- 个人照片
- 姓名
- 一句话自我介绍
- 求职方向：AI 产品经理
- 个人联系方式：微信与手机 `18100839418`
- 邮箱 `1042369137@qq.com`

AI 视觉、创意工具、ToC 产品和 Agent 等细分方向包含在自我介绍中，不单独罗列。

#### 滚动交互

本页没有“开始探索”Logo 或按钮，用户通过自然向下滚动启动故事：

1. 真实照片中的人物逐渐转化为数字化小女孩。
2. 页面中的简历纸或个人介绍卡片脱离原有排版。
3. 纸张逐渐折叠成普通纸飞机。
4. 小女孩坐上纸飞机。
5. 纸飞机载着小女孩向下飞行，进入简历页。

### 5.2 简历页：完整简历

#### 页面目标

完整罗列 PDF 版简历中的内容，让招聘者可以直接阅读正式简历信息。

#### 页面内容

- 按照 PDF 简历的既有信息结构完整展示。
- 页面不把简历信息拆成沿途节点。
- 页面不额外承担经历岛的案例展开功能。
- PDF 文件下载入口固定悬浮在网站右上角，在全部五页中保持可见和可访问。

#### 交互设想

进入本页后，纸飞机与小女孩不再经过任何信息节点。用户继续向下滚动时，纸飞机直接向下飞行并进入经历岛页面。

### 5.3 经历岛：我做过什么

#### 页面目标

集中展示候选人的实习、学校项目和个人 AI 实践。

#### 页面结构

页面右侧为经历岛，左侧为所选经历的详细介绍区域。经历岛在整个页面画幅中约占 30%，避免遮挡左侧主要信息。

经历岛由三个子岛或区域构成：

- 实习经历：约占整体 40%
- 学校项目：约占整体 20%
- 个人 AI 实践：约占整体 40%

面积比例用于表达内容权重，不要求进行严格的几何面积计算。

#### 内容交互

- 小女孩和纸飞机固定在画面中的观察位置，不跟随当前选择移动。
- 用户可以旋转经历岛，将三个子岛中的任意一个转到画面前方。
- 旋转到前方的子岛略微放大，成为当前选中区域；其他子岛保持较小尺度。
- 点击当前子岛后，左侧显示对应分类。
- 点击某段经历，继续展开项目背景、个人行动、结果和复盘。
- 已浏览区域可以留下旗帜、光点或其他低干扰标记。
- 不强迫用户按固定顺序浏览，也不设置必须完成的游戏任务。

#### 离场转场

1. 经历岛保持在原位，不跟随页面移动或缩小。
2. 小女孩离开纸飞机并向下坠落。
3. 纸飞机与经历岛留在原位，逐渐离开小女孩所在画面的视野。
4. 页面从岛屿探索转为纵向坠落。

### 5.4 技能云海：我擅长什么

#### 页面目标

展示候选人的专业能力，并将每项能力与实习、学校项目或个人 AI 实践中的具体证据连接起来。

#### 候选技能

- AI 产品策划
- 用户洞察
- 产品分析与需求定义
- AI 视觉与创意表达
- Prompt 与工作流设计
- Agent 产品思维
- 原型设计
- Vibe Coding
- 数据分析与产品迭代
- 跨团队沟通与项目推进

最终技能数量应根据实际证据收敛，避免过度罗列。

#### 展示方式

- 页面下方是一整团宽阔、柔软的云海。
- 云海上方漂浮着一组“技能条”；技能条是可点击的文字标签，不表示熟练度或进度。
- 用户可以不按顺序随意点击任意技能条。
- 点击某项技能后弹出资料卡片。
- 资料卡说明对该能力的理解、相关经历、代表案例、工具和方法。
- 资料卡提供对应项目入口。
- 不使用缺乏客观依据的技能百分比或进度条。

#### 与经历岛的关系

经历岛和技能云海形成交叉引用：

> 经历证明能力，能力重新串联经历。

例如，“用户洞察”可以同时关联某段实习中的用户研究、某个学校项目中的需求验证，以及某次个人 AI 实践中的反馈迭代。

#### 进入与离开

1. 小女孩从经历岛向下坠落，经历岛始终留在原位。
2. 小女孩离开经历岛所在画面的视野，继续向页面下方落去。
3. 小女孩掉入位于页面下方的一大团柔软云朵中，并舒适地躺在云团上。
4. 云海上方漂浮着一组技能条，用户可以自由选择和查看。
5. 继续向下时，小女孩穿过云层，进入终点页。

### 5.5 抵达终点：与我联系

#### 页面目标

将作品集体验转化为清晰的联系行动，并表达“下一段旅程即将开始”。

#### 页面内容

- 结束语
- 求职意向
- 邮箱与电话
- 微信或其他社交平台
- 下载 PDF 简历
- 复制联系方式
- 联系按钮
- 返回经历岛
- 重新开始旅程

结束语候选：

> 我的探索暂时抵达这里，期待与你一起，让下一个想法真正起飞。

#### 最终画面

小女孩穿过云层后抵达新的平台、山顶或其他开阔场景。纸飞机可以从远处重新出现，暗示她已经准备好再次出发。

## 6. 招聘信息逻辑

五个章节分别回答招聘者的核心问题：

| 章节 | 回答的问题 |
| --- | --- |
| 启程页 | 你是谁，想做什么？ |
| 简历页 | 你的完整履历是什么？ |
| 经历岛 | 你实际做过什么？ |
| 技能云海 | 这些经历证明了哪些能力？ |
| 抵达终点 | 如何联系你？ |

网站的目标印象应是：

> 她有鲜明的创意表达，也知道如何把信息、交互和 AI 能力组织成一个完整产品。

## 7. 全站交互原则

1. 以自然滚动驱动叙事，不依赖“开始探索”按钮。
2. 动画服务于内容理解，不阻止招聘者快速获取信息。
3. 保留固定或易访问的快捷导航，使用户可以直接进入关于我、经历、技能和联系方式。
4. PDF 简历下载入口始终固定悬浮在网站右上角。
5. 重要内容不能只存在于动画中。
6. 不强制招聘者完成游戏化任务后才能查看下一部分。
7. 动画应允许快速略过，并兼顾减少动态效果的系统偏好。
8. 移动端需要保留完整信息，即使适当简化空间运动与角色动画。

## 8. 内容表达原则

### 8.1 经历展示

每段核心经历优先采用以下叙事：

> 问题 → 判断 → 行动 → 结果 → 复盘

避免只列工作职责。能量化的结果应尽量量化；无法公开的数据可使用范围、变化趋势或定性反馈。

### 8.2 技能展示

每项技能至少关联一个真实案例。无法提供案例支撑的技能不作为主要技能展示。

### 8.3 创意与可读性的平衡

- 角色和场景负责建立记忆点。
- 标题、卡片和项目结构负责传递信息。
- 创意不能牺牲文字可读性、导航效率和联系方式的可发现性。

## 9. 成功标准

### 信息效果

- 首屏能快速识别姓名、求职岗位与细分方向。
- 招聘者无需看完动画即可找到简历、经历、技能与联系方式。
- 每项主要技能都能追溯到具体经历。
- 三类经历的层级和权重清晰。

### 体验效果

- 五个章节在空间与故事上连续。
- 照片变角色、纸张折飞机、跳入云海和穿云抵达形成四个清晰记忆点。
- 页面滚动方向和转场动作具有一致的空间逻辑。
- 桌面端和移动端均可完整浏览核心信息。

### 求职效果

- 网站体现 ToC 产品所需的用户意识与体验敏感度。
- 网站体现 AI 视觉、创意工具和 Agent 方向的兴趣与实践。
- 招聘者最终记住候选人的创意表达、产品结构能力和主动实践能力，而不只是动画效果。

## 10. 后续待确认事项

1. 数字化小女孩的具体形象、服装与人物气质。
2. 经历岛三个区域的场景隐喻与区分方式。
3. 技能的最终分类、数量和每项对应证据。
4. 终点场景采用平台、山顶或其他空间。
5. 一句话自我介绍和结束语的最终文案。
6. PDF 简历及各项目素材的最终内容。

网站内容语言已确定为中文。

## 11. 明确不做的内容

- 不使用“开始探索”Logo 或按钮作为进入网站的必要操作。
- 不把纸飞机设计成带驾驶舱、机械结构或光带的未来载具。
- 不使用没有依据的技能熟练度百分比。
- 不将网站设计为必须完成任务才能获取信息的游戏。
- 不让基础资料、项目成果或联系方式只存在于动画中。
- 不设置“沿途探索”页面或基本信息节点；第 2 页仅用于展示完整简历。
